Componentes del curso

Todo lo que necesitas para armar tus pantallas ya está en estilos/ui.css. Esta página muestra cada componente con el HTML que lo produce: cópialo y cámbiale el texto. No escribas CSS propio salvo que algo aquí no exista.

3. Formularios

Cada campo lleva su <label> asociado por for. Sin eso, Lighthouse marca error de accesibilidad y el lector de pantalla no sabe qué se está pidiendo.

Como lo verá el cliente.
Escribe un correo completo, por ejemplo ana@ejemplo.com 
<div class="campo">
  <label class="campo__etiqueta" for="nombre">
    Nombre <span class="requerido">*</span>
  </label>
  <input class="campo__control" id="nombre" type="text">
  <span class="campo__ayuda">Texto de apoyo.</span>
</div>

<!-- Con error: agrega campo--error y el mensaje EN TEXTO -->
<div class="campo campo--error">
  <label class="campo__etiqueta" for="correo">Correo</label>
  <input class="campo__control" id="correo" aria-describedby="e1">
  <span class="campo__error" id="e1">Escribe un correo completo</span>
</div>

12. Responsivo

La aplicación debe funcionar en teléfono, tableta y escritorio: es requisito del proyecto y se audita en la Unidad III. Parte ya viene resuelta; el resto lo decides tú.

Ya se adapta solo

  • .rejilla — reacomoda las tarjetas según quepan
  • .formulario__fila — una columna en teléfono, dos desde tableta
  • .tabla-scroll — la tabla se desplaza en horizontal
  • .pestanas — la barra de pestañas se desplaza
  • .contenedor — se centra y limita su ancho

Lo decides tú en cada pantalla

  • Cuántas columnas usa cada vista
  • Qué acciones caben en teléfono y cuáles se mueven de lugar
  • Si tu tabla se desplaza en horizontal o se convierte en tarjetas
  • Cómo se ve tu formulario en una pantalla de 360 px de ancho

Puntos de quiebre del curso. Diseña primero para teléfono:

/* teléfono: es lo que escribes fuera de cualquier @media */
.mi-clase { ... }

@media (min-width: 640px)  { /* tableta */ }
@media (min-width: 1024px) { /* escritorio */ }

Utilidades listas para usar:

<!-- Columnas que colapsan a una sola en teléfono -->
<div class="cols cols--2">…</div>
<div class="cols cols--3">…</div>

<!-- Contenido principal con barra lateral -->
<div class="con-lateral"><main>…</main><aside>…</aside></div>

<!-- Mostrar u ocultar según el tamaño -->
<span class="oculto-movil">Solo se ve desde tableta</span>
<span class="oculto-escritorio">Solo se ve en teléfono</span>

<!-- Botones a todo lo ancho en teléfono -->
<div class="acciones acciones--apilar">…</div>
Cómo lo pruebas. Abre las herramientas del navegador, activa la vista de dispositivo y revisa a 360 px de ancho, que es un teléfono común. Si algo se desborda a lo ancho, está mal.

13. Reglas que no debes romper

  • No quites el contorno del foco. Es requisito de accesibilidad y baja el puntaje de Lighthouse.
  • Todo <input> lleva su <label> asociado por for.
  • Ningún control mide menos de 44 px de alto.
  • El color nunca es la única señal: los estados y los errores siempre llevan texto.
  • Toda tabla va dentro de .tabla-scroll.
  • Nada se desborda a lo ancho en una pantalla de 360 px.
  • Si necesitas algo que no está aquí, pídelo antes de escribir CSS propio.
